# Supporting collections and relational dependencies

All entries here are part of phase 1 even where they have no standalone operation. Shared notation and boundary rules are in [README](README.md). Source types/enums are preserved in [schema evidence](schema-evidence.md). Each embedded dependency is fetched with its parent; it has no independent list/get/search/facet/resource contract unless explicitly stated. Parent filters and pagination remain the only public inputs. Embedded IDs identify source records, not junction rows.

## Named supporting collections

These five collections are intentionally included through core details. Standalone public list/get is deferred pending a demonstrated lookup use case; there is no documented standalone Algolia index for any of them. This preserves their information without introducing five separate browsing surfaces.

No recursive reverse article expansion.                                               | Schema requires title/url; actual URL validity and upstream access TBD. Algolia embedding only documents id/title, so fetch URL from Directus.                  |

## Taxonomy dependencies

Taxonomies are embedded filter vocabulary, not standalone content collections, except `sectors` (see [core](core.md)). Implemented `readTaxonomy` normalizes each to `Taxonomy={id:GUID,title:string,slug:string|null,description:string|null}`. `get_filters` supplies choices rather than list/search/facets/resources for these collections. IDs are GUID-shaped, deliberately allowing non-RFC UUID version bits. Current helper fetches all choices with stable ID order; this is independent of parent list pagination.

| Collection / purpose                  | Inputs and output mapping / relationships                                                                        | Exposure / evidence / unresolved points                                                                                                                        |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `topics` / subjects                   | Parent list GUID arrays; Topic.name → title; slug/description retained. Article, FAQ, testimonial, episode tags. | Embedded/filter-only; no own index documented. Existing helper verifies mapping; actual values discovered at runtime.                                          |
| `qualifications` / qualifications     | Parent list GUID arrays; Qualification.name → title. Article/program tags.                                       | Embedded/filter-only; no own index documented. Qualification.sectors is not recursively expanded.                                                              |
| `roles` / professional roles          | Parent list GUID arrays; Role.name → title. Article/program/testimonial/episode/profile tags.                    | Embedded/filter-only; no own index documented. Role.sectors remains outside normalized lookup shape.                                                           |
| `tracks` / pathways                   | Parent list GUID arrays; Track.name → title. Article/testimonial/episode tags and ProgramForm.track M2O.         | Embedded/filter-only. Do not invent a Program.tracks relation; program tracks are reached through forms.                                                       |
| `school_subjects` / teaching subjects | Parent program GUID arrays; SchoolSubject.name → title, slug/description retained.                               | Embedded/filter-only, already supported by readTaxonomy. No documented program search facet for this relation.                                                 |
| `phases` / journey stage              | Parent list GUID arrays; Phase.title → title, slug is null because no source slug; description retained.         | Embedded/filter-only. Source code/quote/color are not required in filter output.                                                                               |
| `audiences` / intended readership     | Parent list GUID arrays; Audience.title → title; absent slug/description normalize to null.                      | Embedded/filter-only. Source sort/color/alt_names are outside normalized filter output.                                                                        |
| `sectors` / education sectors         | Parent GUID array filters and Taxonomy projection coexist with standalone Sector content.                        | Dual exposure intentionally retained; same source ID must be used for filtering and document retrieval. No recursive sector content inside every taxonomy tag. |

All taxonomy filter arrays follow README bounds and AND/OR semantics. `get_filters` metadata describes matching rules and current choices without counts; countable Algolia facet values are separate inputs and may be labels rather than IDs.

## Relationship shapes and flattening

`ArticleRef={id:ID,title:string,source_url:URL|null}`, `FaqRef={id:ID,question:string,source_url:URL|null}`, `InstitutionRef={id:ID,title:string,source_url:URL|null,logo:Asset|null,type:EducationalInstitution.type}`, `ShowRef={id:ID,title:string,source_url:URL|null,artwork:Asset|null,podcast_status:PodcastShow.podcast_status,creator_name:string}`. `MediaRef={collection: videos|podcast_episodes|testimonials,id:ID,title:string,source_url:URL|null}`. Reference source URLs follow actual target paths; FAQ stays null until a route is verified. Reference-only videos do not imply standalone video tools.

All Directus M2M junctions connecting selected parents and targets are **indirect**, never public collections. Inputs are target ID arrays; outputs are the target shapes above. Resolve the actual target key (`authors_id`, `profiles_id`, `podcast_hosts_id`, `<taxonomy>_id`, etc.), discard junction IDs and parent backlinks, and preserve meaningful sort order. M2A uses both collection and item identity, with an explicit allowlist; never dispatch arbitrary collection names. Missing targets and null junction items need warnings or a safe error rather than disappearing silently. Duplicate-target handling and per-relation caps are TBD from fixtures.

Content dependencies `articles_editor_nodes`, `testimonials_editor_nodes`, `callouts_editor_nodes`, `buttons`, `callouts`, `images`, `mediaplayers`, `content_lists`, `content_list_items`, `related_content_lists`, `related_content_lists_items`, `mentions` and `mentions_item` are **indirect renderer dependencies**. Public operations/resources/filters are absent. Parent body document + scoped editor-node expansions produce Markdown/warnings/truncated; they do not become separate records. Exact generated table names must be taken from `Schema`, not derived from these interface labels. Existing renderer projections are authoritative; do not fetch all fields. Unknown node types remain explicit warnings. Other core collections lack editor_nodes in their generated interfaces and cannot assume these junctions exist.

This inventories the requested nine core and five supporting collections, seven additional taxonomy collections (sectors counted once), six embedded dependencies including files, and the deferred/excluded families. Counts are explanatory; there is no goal to publish 25–30 standalone collections.

Article evidence and testimonial support implements sources/documents/authors through article detail and authors/minimal profiles through testimonials. See [implemented contracts and evidence](article-evidence-and-testimonials.md) for nullable URLs, bounded relations, verified PDF delivery and profile-biography deferral; these supersede the original TBDs above for those projections.

Institutions and programs implements locations, availability and program forms through institutions/programs. [Verified contracts](institutions-and-programs.md) supersede original TBDs: GeoJSON points preserve longitude/latitude, weekly schedules retain local time strings without open-now inference, unavailable location sync time is null, and program forms render independently with parent verification and explicit relation bounds.
